# Document Requests - Database Table Structure

## Overview
This document describes the database structure for storing document requests (both active and old documents). Data is split between:
- **PostgreSQL/Supabase** (`requesters_analytics` table) - for analytics and structured data
- **MongoDB** (`requests` collection) - for detailed request information including long text and arrays

---

## PostgreSQL/Supabase Table: `requesters_analytics`

### Table Schema

```sql
CREATE TABLE requesters_analytics (
  id SERIAL PRIMARY KEY,
  request_id VARCHAR(255) NOT NULL UNIQUE,  -- Foreign key to MongoDB _id
  user_type VARCHAR(50) NOT NULL,           -- 'student' or 'guest'
  email VARCHAR(255) NOT NULL,
  status VARCHAR(50) DEFAULT 'pending',     -- 'pending', 'approved', 'rejected'
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  updated_at TIMESTAMP,
  
  -- PUPian (student) fields
  program VARCHAR(255),                     -- Program/College name
  department VARCHAR(255),                  -- Department name
  role VARCHAR(50),                        -- 'Student' or 'Faculty'
  
  -- Guest fields
  full_name VARCHAR(255),                   -- Guest full name
  city VARCHAR(255),                        -- Guest city
  country VARCHAR(255),                      -- Guest country
  school VARCHAR(255),                       -- University/Organization name
  
  -- Indexes
  INDEX idx_request_id (request_id),
  INDEX idx_user_type (user_type),
  INDEX idx_status (status),
  INDEX idx_created_at (created_at)
);
```

### Field Mapping by Form Type

#### PUPian Form Fields → Table Columns:
| Form Field | Table Column | Type | Required |
|-----------|--------------|------|----------|
| `currentUserEmail` | `email` | VARCHAR(255) | Yes |

| `pupianRole` | `role` | VARCHAR(50) | Yes |
| - | `user_type` | VARCHAR(50) | Yes (set to 'student') |
| - | `request_id` | VARCHAR(255) | Yes (from MongoDB) |

#### Guest Form Fields → Table Columns:
| Form Field | Table Column | Type | Required |
|-----------|--------------|------|----------|
| `guestEmail` | `email` | VARCHAR(255) | Yes |
| `guestFullName` | `full_name` | VARCHAR(255) | Yes |
| `guestCity` | `city` | VARCHAR(255) | Yes |
| `guestCountry` | `country` | VARCHAR(255) | Yes |
| `guestSchool` | `school` | VARCHAR(255) | Yes |
| `guestProgram` | `program` | VARCHAR(255) | Yes |
| `guestDepartment` | `department` | VARCHAR(255) | Yes |
| `guestRole` | `role` | VARCHAR(50) | Yes |
| - | `user_type` | VARCHAR(50) | Yes (set to 'guest') |
| - | `request_id` | VARCHAR(255) | Yes (from MongoDB) |

### Notes:
- `request_id` stores the MongoDB `_id` as a string (foreign key relationship)
- `user_type` distinguishes between 'student' (PUPian) and 'guest' (non-PUP)
- For PUPian: `full_name`, `city`, `country`, `school` will be NULL
- For Guest: all fields are populated
- `role` field needs to be added manually to the table (as mentioned by user)

## MongoDB Collection: `requests`

### Document Schema

```javascript
{
  _id: ObjectId,                    // Primary key, used as foreign key in requesters_analytics
  document_id: String,              // ID of the requested document
  user_type: String,                // ✅ Only redundant field: 'student' or 'guest'
  purpose: String,                  // Long text - purpose of request
                                      // Active: min 24 chars, Old: min 50 chars
  intendedUse: String,              // Long text - intended use (old docs only, min 24 chars)
  howDidYouLearn: String,           // Long text, optional (old docs only)
  chaptersRequested: [String]       // Array: ['Chapter 1', 'Chapter 2', ...] or ['All']
}
```

**Note:** All structured requester data (email, program, department, role, full_name, city, country, school, supervisor, contact_number, consent_to_contact, preferred_contact_method) is stored **only** in the PostgreSQL `requesters_analytics` table, not in MongoDB.

## Data Flow

### Submission Process:

1. **User fills form** (PUPian or Guest)
2. **Frontend validates** form data
3. **Frontend sends POST request** to `/requests/` endpoint with flattened structure:
   ```javascript
   {
     // MongoDB fields
     document_id: string,
     user_type: 'student' | 'guest',
     chaptersRequested: string[],
     purpose: string,
     intendedUse: string,  // Old docs only
     howDidYouLearn: string,  // Old docs only, optional
     
     // Structured data for PostgreSQL table
     email: string,
     program: string,
     department: string,
     role: string,
     full_name: string,  // Guest only
     city: string,  // Guest only
     country: string,  // Guest only
     school: string,  // Guest only
     supervisor: string,  // Old docs only, optional
     contact_number: string,  // Old docs only
     consent_to_contact: boolean,  // Old docs only
     preferred_contact_method: string  // Old docs only
   }
   ```

4. **Backend extracts MongoDB fields** and creates MongoDB document:
   - Generates `_id` (ObjectId)
   - Stores only: `document_id`, `user_type`, `purpose`, `intendedUse`, `howDidYouLearn`, `chaptersRequested`

5. **Backend extracts structured data** and creates Supabase record:
   - Uses MongoDB `_id.toString()` as `request_id`
   - Stores all structured requester data for analytics
   - Excludes long texts and arrays (stored only in MongoDB)

### Relationship:
```
MongoDB.requests._id (ObjectId)
    ↓ (converted to string)
requesters_analytics.request_id (VARCHAR)
```

---

## Fields NOT Stored in Table (MongoDB Only)

These fields are stored **only** in MongoDB, not in the `requesters_analytics` table:

1. **`purpose`** (String)
   - Reason: Long text field, not suitable for table storage
   - Location: MongoDB `requests.purpose`
   - Validation: Minimum 24 characters

2. **`chaptersRequested`** (Array of Strings)
   - Reason: Array data, can have multiple values
   - Location: MongoDB `requests.chaptersRequested`
   - Values: `['Chapter 1', 'Chapter 2', ...]` or `['All']`

## Backend API Endpoint

### POST `/requests/`

**Request Body:**
```javascript
{
  document_id: string,              // Required
  userType: 'student' | 'guest',    // Required
  requester: {                       // Required
    // PUPian:
    email: string,
    program: string,
    department: string,
    role: string,
    
    // Guest:
    fullName?: string,
    city?: string,
    country?: string,
    school?: string,
    program?: string,
    department?: string,
    role?: string
  },
  chaptersRequested: string[],       // Required, array
  purpose: string                    // Required, min 24 chars
}
```

**Response:**
```javascript
{
  message: "Request submitted",
  requestId: "507f1f77bcf86cd799439011"  // MongoDB _id as string
}
```

## Summary

- **Table (`requesters_analytics`)**: Stores structured data for analytics, excludes long text and arrays
- **MongoDB (`requests`)**: Stores complete request data including `purpose` (long text) and `chaptersRequested` (array)
- **Relationship**: `requesters_analytics.request_id` = `requests._id.toString()`
- **Role field**: Needs to be manually added to `requesters_analytics` table
