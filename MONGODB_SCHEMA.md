# MongoDB `requests` Collection - Complete Schema

## Overview
This document describes the **flattened** MongoDB structure for storing document requests. MongoDB stores **only** long text fields and arrays. All structured data is stored in the PostgreSQL `requesters_analytics` table.

**Key Principle:** No redundant data. Only `user_type` is stored in both MongoDB and PostgreSQL.

---

## MongoDB Document Structure

### New Flattened Structure (No Redundancy)

```javascript
{
  _id: ObjectId,                    // Primary key, auto-generated
  document_id: String,              // Which document was requested (thesis._id)
  user_type: String,                // ✅ Only redundant field: 'student' or 'guest'
  purpose: String,                  // Long text - purpose of request
  intendedUse: String,              // Long text - intended use (old docs only)
  howDidYouLearn: String,           // Long text, optional (old docs only)
  chaptersRequested: [String]       // Array: ['Chapter 1', 'Chapter 2', ...] or ['All']
}
```

### Field Descriptions

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `_id` | ObjectId | Yes | Primary key, auto-generated by MongoDB |
| `document_id` | String | Yes | The ID of the document being requested |
| `user_type` | String | Yes | Either `'student'` (PUPian) or `'guest'` (non-PUP) - **Only redundant field** |
| `purpose` | String | Yes | Long text describing the purpose of the request (min 24 chars for active, min 50 for old) |
| `intendedUse` | String | No | Long text describing intended use (old documents only, min 24 chars) |
| `howDidYouLearn` | String | No | Optional long text describing how requester learned about document (old documents only) |
| `chaptersRequested` | Array[String] | Yes | Array of requested chapters, e.g., `['Chapter 1', 'Chapter 2']` or `['All']` |

---

## What is NOT in MongoDB (Stored in PostgreSQL Table Only)

The following fields are **NOT** stored in MongoDB (they are in the `requesters_analytics` table):

- `email`
- `program`
- `department`
- `role`
- `full_name`
- `city`
- `country`
- `school`
- `supervisor`
- `contact_number`
- `consent_to_contact`
- `preferred_contact_method`
- `status`
- `created_at`
- `updated_at`

## Data Flow

### Submission Process:

1. **Frontend sends flattened payload** to `/requests/` endpoint:
   ```javascript
   {
     // MongoDB fields
     document_id: "6904ddf8c9ed2a6aac59cf07",
     user_type: "guest",
     purpose: "Long text...",
     intendedUse: "Long text...",  // Old docs only
     howDidYouLearn: "Long text...",  // Old docs only, optional
     chaptersRequested: ["Chapter 1", "Chapter 2"],
     
     // Structured data for PostgreSQL table
     email: "user@example.com",
     program: "Computer Science",
     department: "Department of CS",
     role: "Student",
     full_name: "John Doe",  // Guest only
     city: "Manila",  // Guest only
     country: "Philippines",  // Guest only
     school: "University of the Philippines",  // Guest only
     supervisor: "Dr. Smith",  // Old docs only, optional
     contact_number: "09123456789",  // Old docs only
     consent_to_contact: true,  // Old docs only
     preferred_contact_method: "Email"  // Old docs only
   }
   ```

2. **Backend extracts MongoDB fields** and creates MongoDB document:
   ```javascript
   {
     document_id: "6904ddf8c9ed2a6aac59cf07",
     user_type: "guest",
     purpose: "Long text...",
     intendedUse: "Long text...",
     howDidYouLearn: "Long text...",
     chaptersRequested: ["Chapter 1", "Chapter 2"]
   }
   ```

3. **Backend extracts structured data** and creates PostgreSQL record:
   ```sql
   INSERT INTO requesters_analytics (
     request_id, user_type, email, program, department, role,
     full_name, city, country, school, supervisor, contact_number,
     consent_to_contact, preferred_contact_method, status, created_at
   ) VALUES (...);
   ```

## Relationship with PostgreSQL

```
MongoDB.requests._id (ObjectId)
    ↓ (converted to string)
requesters_analytics.request_id (VARCHAR)
```

The `request_id` in PostgreSQL is the string representation of MongoDB's `_id`, creating a foreign key relationship.

## Summary

**MongoDB stores:**
- ✅ Long text fields (`purpose`, `intendedUse`, `howDidYouLearn`)
- ✅ Array fields (`chaptersRequested`)
- ✅ `user_type` (only redundant field, as specified)
- ✅ `document_id` (which document was requested)

**MongoDB does NOT store:**
- ❌ Structured requester data (email, program, department, etc.)
- ❌ Status, timestamps (these are in PostgreSQL)
- ❌ Short text fields (supervisor, contact_number, etc.)

**Total MongoDB Fields: 7**
1. `_id` (ObjectId, auto-generated)
2. `document_id` (String)
3. `user_type` (String) - Only redundant field
4. `purpose` (String)
5. `intendedUse` (String, optional, old docs only)
6. `howDidYouLearn` (String, optional, old docs only)
7. `chaptersRequested` (Array[String])
